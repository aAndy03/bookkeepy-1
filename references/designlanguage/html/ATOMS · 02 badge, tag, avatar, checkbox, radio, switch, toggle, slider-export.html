design system v1.7.1
updated 2026-10-19 · see CHANGELOG
bookkeepy · atoms 02
Badge, Tag, Avatar, Checkbox, Radio, Switch, Toggle, Slider.
Same structure as atoms 01: behaviour API first, then every state it can produce. New here: states are real variants. Each master reads component tokens (sel-bg, sw-track, tag-fg …) whose values change per theme axis; an instance only sets its theme.
theme axis · interaction
rest · hover · pressed · focus · disabled
every interactive atom; drives fills, borders, ring, opacity
theme axis · checked
off · on · mixed
checkbox, radio, switch, toggle; also shows/hides marks via boolean tokens
theme axis · tone
neutral · accent · success · warning · danger · info
badge, tag; one semantic color family per value
how to use
select an instance → set theme { interaction: hover, checked: on }. A parent frame can set an axis for everything inside it. Default is the first value of each axis.
